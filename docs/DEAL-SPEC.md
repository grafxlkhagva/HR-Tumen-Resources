# Deal хэсгийн бүтэн spec (амьд баримт)

> CX manager-ийн CRM-ийг төгс болгох ажлын хүрээнд Deal хэсгийн зорилго, бүтэц,
> хийх ажлын жагсаалт. **Энэ файлыг хөтөлж, гүйцэтгэлийг тэмдэглэж явна** —
> ингэснээр юу хийсэн/хийгээгүй мартагдахгүй.

## 1. Бизнесийн контекст (Түмэн Тээх)

- Тээврийн **цогц үйлчилгээ**: Олон улс · Орон нутаг · Хот доторх хүргэлт/түгээлт · Томоохон төсөл
- **3 баг** (тус бүр KAM-тай, зорилт/плантай):
  - Орон нутаг — Нямдорж, Баяраа
  - Олон улс — Амар
  - Төсөл/Түгээлт — Одонтунгалаг, Отгонбаатар
- Нийт **12 ажилтан**
- Харилцагч: 2022-оос **B2B томоохон** (давтан) + **нэг удаагийн** (олон)
- Гол зорилго: харилцагч + харилцагч болгохыг удирдах, сар бүр план, бодит явцыг дүгнэх

## 2. Deal-ийн үндсэн зарчим

1. **Deal бол хамгийн гол хэсэг** — эхний ээлжинд үүнийг зөв авч явна.
2. Deal бүр: **үйлчилгээний төрөл → баг → KAM → зорилт/план**-д нийлнэ.
3. Орж ирэх: **~98% гаднаас (MQL)** [утас/SMS/имэйл/форм/FB/CallPro], цөөн нь дотоод (SQL).
4. Амьдралын мөчлөг: `lead → opportunity → won`, хажуугаар `pending`/`lost` (шалтгаантай).
5. **Нэг удаагийн vs давтан B2B** — өөр урсгал:
   - Нэг удаагийн: won → дуусна (үргэлжлэх account шаардлагагүй)
   - B2B: won → компани `customer` болж, тогтмол захиалга/NPS/churn хяналтад шилжинэ
6. **Хугацаа/SLA мэдэрч, signal явж, замбараагүй биш** байх.

## 3. Дата загвар (Deal талбарууд)

Одоо байгаа: `name, amount, currency, stageId, contactId, companyId, kam, source,
sourceType(mql/sql), direction, cargo, phone, customerType, quoteDue, quotedAt,
lostReason, leadKey, closedAt`.

Нэмэх/тодруулах санал:
- [ ] **serviceType** (Олон улс / Орон нутаг / Хот доторх түгээлт / Төсөл) — одоо зөвхөн KAM→team-ээр дам. Тодорхой талбар болгох уу? (баг/аналитик цэвэр болно)
- [ ] **dealType** (давтан B2B / нэг удаагийн) — мөчлөг ялгахад
- [ ] Company **optional** (нэг удаагийн/хувь хүн бол хоосон) — аль хэдийн optional

## 4. Хийх ажлын жагсаалт (эрэмбэтэй)

### Дууссан ✅
- [x] Deal analytics (funnel/баг/KAM хүснэгт/эх сурвалж) — прототипийн яг томьёо
- [x] Board шүүлтүүр (хайлт/KAM/суваг/MQL-SQL)
- [x] Lead баганыг quote_due-ээр эрэмбэлэх
- [x] Картан дээр шат солих dropdown

### Дараагийн ээлж 🔨
- [ ] Картан дээрх түргэн форм (тэмдэглэл/KAM/огноо/компани холбох)
- [ ] Deal дор нэгдсэн timeline (дуудлага/SMS/имэйл/note нэг урсгалд)
- [ ] SLA цаг: "дараагийн эцсийн хугацаа" + хэтэрвэл эскалаци signal
- [ ] serviceType / dealType талбар (шийдвэрээс хамаарч)

### Том зорилт 🎯
- [ ] Гадаад суваг → лийд холболт (SMS/имэйл орж ирэхэд deal үүсгэх/холбох)
- [ ] Авто-оноолт (эх сурвалж/чиглэл → баг/KAM)
- [ ] Pipeline эрүүл мэнд (үе шат хоорондын хөрвөлт, гацсан цэг)
- [ ] Deal → сарын план/зорилт бодит нэгтгэл + явц дүгнэлт

## 5. Нээлттэй шийдвэрүүд (хэрэглэгчээс)

- serviceType-ыг тусдаа талбар болгох уу, эсвэл KAM→team дам хангалттай юу?
- dealType (давтан/нэг удаагийн) хэрэгтэй юу?
- Гадаад сувгийн баг ямар шатанд — давхцахгүйн тулд аль хэсгээс эхлэх?
